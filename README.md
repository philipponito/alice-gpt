# Мой GPT — Алиса + Google

## Поиск в интернете через Serper

В Production Vercel добавьте ключ Serper как `ALICE_GPT_SEARCH` и опубликуйте версию с `lib/web-search.mjs`. Одной переменной без кода инструментов недостаточно. По смыслу текущей просьбы модель выбирает `web_route`; публичный поиск запускается отдельным агентом через тот же фоновый механизм и доставку на колонку. Личный Google-аккаунт для него не нужен. Google-инструменты и контекст писем/документов этому агенту недоступны. Публичный поисковый контекст шифруется отдельно и истекает через пять минут.

Выполняется не более двух запросов Serper за задачу, по пять результатов. Ключ передаётся только в заголовке `X-API-KEY` к фиксированному HTTPS endpoint `google.serper.dev/search`, не модели. Произвольные страницы по ссылкам не загружаются: ответы основаны на поисковых фрагментах. Ошибки ключа и лимита Serper сообщаются пользователю без содержимого ошибок провайдера. Использование расходует запросы текущего тарифа Serper; код не покупает дополнительные запросы.

## Напоминания

Для личных напоминаний выберите дополнительное разрешение `calendar.events.owned` при подключении Google и укажите его в Google Cloud Data Access. Явная просьба «напомни завтра в 11 позвонить» создаёт личное 15-минутное событие основного календаря без дополнительного подтверждения, с popup-уведомлениями за 30 минут и в момент начала. Явная просьба перенести или удалить событие выполняется после свежего поиска; неоднозначный выбор требует уточнения. Перенос сохраняет длительность, изменения защищены версией события и дедупликацией запроса. Повторы, события на весь день и чужие события не изменяются. За запрос можно удалить не более пяти событий. При неизвестном результате проверьте календарь перед повтором. Уведомления зависят от настроек устройств. Это события Google Calendar, а не Google Tasks.

Существующий GPT (`gpt-6-luna`), команды выхода и ключи памяти `alice:v1:<hash>:history/facts` сохранены. Google работает отдельным фоновым запросом на Vercel. Диск поддерживает поиск названий файлов, Google Docs — чтение содержимого, Gmail — чтение писем. Отправка писем и правка документов отключены. Текст письма можно подготовить в ответе Алисы.

## Настройка

Production environment variables (только в Vercel, не в Git):

- `OPENAI_API_KEY`, `ALICE_WEBHOOK_SECRET` (случайный секрет длиной не менее 32 символов).
- `KV_REST_API_URL`, `KV_REST_API_TOKEN` — существующий Upstash Redis.
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` — OAuth web client.
- `GOOGLE_REDIRECT_URI` = `https://alice-gpt-eta.vercel.app/api/google/callback`.
- Необязательно: `GOOGLE_SETUP_SECRET` — отдельный ключ владельца для формы подключения. По умолчанию применяется существующий `ALICE_WEBHOOK_SECRET`.
- Необязательно: `GOOGLE_TOKEN_ENCRYPTION_KEY` — независимый случайный секрет от 32 символов. Иначе ключ шифрования выводится из `ALICE_WEBHOOK_SECRET` через HKDF с отдельным контекстом. Смена использованного секрета делает старые Google-токены нечитаемыми: потребуется повторная привязка. Память Алисы от этого не меняется.

В Google Cloud включить Calendar, Drive, Docs и Gmail API. В web client разрешить ровно указанный redirect URI. В Data Access объявить:

```
openid
https://www.googleapis.com/auth/calendar.events.readonly
https://www.googleapis.com/auth/drive.metadata.readonly
https://www.googleapis.com/auth/documents.readonly
https://www.googleapis.com/auth/gmail.readonly
```

Доступ к Диску ограничен поиском метаданных; содержимое читается только у Google Docs. Файлы PDF, Word, Sheets и вложения писем не скачиваются. Календарь — основной (`primary`), максимум 20 событий за запрос до 93 дней; поиск Диска — до 10 файлов, Gmail — до 5 писем. Неполные результаты помечаются для модели. Нельзя обещать поиск по всему содержимому Диска.

Google Cloud display name: `alice-gpt-google`; project ID: `feisty-script-514722-d5`.

## Привязка

1. В навыке под авторизованным Яндекс-пользователем сказать «подключи Google». Получить одноразовый десятизначный код (10 минут).
2. Открыть `https://alice-gpt-eta.vercel.app/api/google/connect` кнопкой в Алисе или вручную. Ввести код и ключ настройки владельца **только на этом сайте**, выбрать сервисы.
3. Пройти Google consent в этом же браузере. Ни пароль Google, ни ключи не отправлять в чат. Страница объясняет передачу запрошенных данных OpenAI для ответа.
4. После страницы «Google подключён» спросить «какие встречи завтра», «найди документ …» или «какие непрочитанные письма». После короткого подтверждения сказать «готово». Повторный «готово» возвращает тот же ответ в течение 5 минут.
5. «Статус Google» перечисляет сервисы из сохранённых разрешений; это не проверка действительности refresh token. Запрос чтения проверяет реальный доступ.

Устройства без `session.user.user_id` не получают Google-данные. Привязка изолирована по пользователю и навыку. Разные Яндекс-пользователи привязываются отдельно. Перепривязка к другому Google-аккаунту отвергается, чтобы случайно не подменить владельца; смена аккаунта требует административного удаления только его ключа Google-токенов. Для отзыва доступа используйте настройки безопасности Google-аккаунта.

## Безопасность и время ответа

- POST webhook продолжает проверять `ALICE_WEBHOOK_SECRET` в `?key=`. Не публикуйте полный URL, не включайте его в логи или скриншоты. Платформенные access logs могут содержать query; их доступ и retention нужно контролировать отдельно.
- Форма подключения: same-origin POST, CSRF cookie, ключ владельца, ограничение попыток. OAuth: случайный одноразовый state, cookie HttpOnly/Secure/SameSite=Lax, PKCE S256 и TTL 10 минут. Callback не отражает и не журналирует коды/ошибки провайдера.
- AES-256-GCM шифрует токены, pairing/state, результат и краткий контекст Google в Redis. AAD привязывает шифротекст к конкретному ключу пользователя. Refresh token сохраняется при обновлении access token. Ошибка `invalid_grant` требует нового consent.
- Запросы чтения Google используют фиксированный список GET-инструментов, HTTPS origins и валидацию аргументов; redirect запрещён. Отдельные операции создания/изменения календаря требуют соответствующего разрешения и явной просьбы пользователя. Письма и документы считаются недоверенными данными.
- Модель определяет необходимость Google по смыслу и недавнему контексту, затем поиск запускается через `waitUntil`. Приветствие, выход и команды памяти сохраняют прежнее поведение.
- Один активный Google job на пользователя; повтор webhook дедуплицируется. Задача ограничена 42 секундами, Vercel function — 60. Redis foreground calls имеют timeout 700 мс. Память и короткий Google-контекст читаются одним запросом. Бюджет маршрутизации резервирует 700 мс для сохранения результата или запуска задачи; фоновый поиск ожидается только до трёх секунд от начала обработчика. Это оставляет запас до лимита Яндекса, но не гарантирует время холодного запуска и сети Vercel.
- `waitUntil` не является долговечной очередью. При аварийном завершении/таймауте job истекает. При неизвестном результате записывающей операции нужно проверить календарь перед повтором.
- Контекст Google и ответы удаляются по TTL 5 минут; содержимое не попадает в постоянную память. Запросы OpenAI используют `store:false` (это не обещание zero data retention со стороны провайдера).

## Ограничения Google OAuth

External + Testing с этими scopes обычно выдаёт refresh token на 7 дней. Для личного проекта владелец уже перевёл OAuth-приложение в Production и повторно предоставил доступ. Production убирает именно ограничение Testing; Google всё ещё может отозвать доступ по другим причинам, например после отзыва разрешения пользователем или изменения пароля при Gmail scopes. Новые проекты настраиваются отдельно.

`gmail.readonly` и `drive.metadata.readonly` относятся к restricted scopes, `documents.readonly` и Calendar — sensitive. Для публичного распространения применяются verification и, в зависимости от использования restricted data, требования security assessment. Google предусматривает исключения для личного использования/ограниченной аудитории; наличие исключения и требования конкретного проекта необходимо проверить в консоли. Нельзя обещать, что одного переключения Production достаточно. Приложение не публикуется для посторонних.

Источники: [Google web OAuth](https://developers.google.com/identity/protocols/oauth2/web-server), [срок refresh token](https://developers.google.com/identity/protocols/oauth2#expiration), [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes), [Drive scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth), [Docs scopes](https://developers.google.com/workspace/docs/api/auth), [Яндекс: 4,5 секунды](https://yandex.ru/dev/dialogs/alice/doc/ru/response), [Vercel waitUntil](https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package#waituntil).

## Проверка и публикация

`npm ci --ignore-scripts` и `npm test`. Тесты используют только искусственные аккаунты, поддельные токены и mock API, не обращаются к почте/календарю. Проверяются OAuth CSRF/replay/PKCE, изоляция пользователей, refresh, allowlist, память, выход и быстрый ответ с фоновым результатом.

Сначала проверить отдельную ветку/preview. Production-секреты не копировать в preview. После публикации проверить GET health, POST без ключа (403), callback без state (400), страницу подключения, затем реальную привязку и по одному запросу чтения. Не создавать тестовых писем или событий. Для отката восстановить предыдущий deployment; ключи памяти сохраняются.


## Единый агент Luna

По умолчанию обычные реплики обрабатывает `lib/agent.mjs`: один цикл OpenAI Responses с инструментами Google Calendar, Drive/Docs, Gmail, публичного поиска, памяти и света. Модель сама выбирает последовательность инструментов; отдельные google_route/web_route не требуются. Технические команды подключения, выхода, получения ответа и быстрые однозначные команды света сохраняют прежний путь.

Общий контекст хранится зашифрованно в Redis до 5 минут, целыми парами вызовов/результатов, до четырёх ходов и 60 КБ. Личные Google-результаты не попадают в бессрочную историю. После приватного чтения внешний поисковый запрос восстанавливается отдельной проверкой только из пользовательского запроса и обычной истории, без Google-содержимого или предложенного моделью запроса. Факты используют прежние ключи памяти.

Каждый запрос защищён квитанцией выполнения и блокировкой пользователя. Изменения календаря требуют текущего чтения событий и прежних серверных проверок, одно записывающее действие на ход. Создание приглашений, отправка Gmail и правка документов не добавлены. Медленные ответы доставляются прежним мостом Home Assistant. Периодическое поддержание навыка остаётся отключено.

Для аварийного возврата к прежнему обработчику можно установить `ALICE_AGENT_MODE=legacy` и перепубликовать сервер. Набор `test/agent.test.mjs` проверяет новый путь; прежний набор явно использует режим legacy для проверки совместимости старого пути и общих компонентов.
